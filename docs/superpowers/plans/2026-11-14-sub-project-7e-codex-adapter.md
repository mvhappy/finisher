# Sub-project 7E: The Codex adapter — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task names a **model tier** for its implementer: `opus` for semantics (the protocol mapping, permissions, the Finisher-run shell, budgets against a process we do not control, isolation checks, resume, rollback and crash paths, account checks, Windows), `sonnet` for plumbing (the pin script, the fake's script runner, detection, console, data files, transcripts, e2e, docs). Tasks 0 and 20 are controller-run (they need a person-signed-in Codex and other hosts); Task 15's last step needs the Windows host.

**Goal:** a person can start an agent session on **the Codex app-server Finisher bundles (the pinned version only, spec §4.6), signed in by the user with the CLI's own `codex login`**, and it behaves like every other harness. After 7E:
- `agent.session.start {harness: "codex"}` runs `codex app-server --listen stdio://` with per-session `-c` overrides, **inside the session sandbox** (`openSessionSandbox`, 7C), `CODEX_HOME` = the session's `provider/` directory, the sign-in store reached in place (`provider/auth.json` → `providers/codex/home/auth.json`, `SIGN_IN_STORES.codex`, `apps/finisherd/src/agent/session-dirs.ts:252`);
- threads, turns, items, reasoning summaries and token usage become the runtime's `ProviderEvent`s (spec §4.1), so nodes, budgets, the journal and the trace store need nothing new;
- **every command the agent runs is Finisher's**: Codex's own shell tools are off and a `shell` dynamic tool is answered by `finisherd`, which decides it through 7B's `permissions.ts` and runs it through the session sandbox with `FIN_CALL` set (exact attribution, the same on Windows; Decision 9, Owner question 2); Codex's file changes (`apply_patch`) and other `*/requestApproval` requests go through `provider-requests.ts` the same way;
- interrupt, steer, crash, resume (`thread/resume`), **rollback (`thread/revert`)**, the pinned-version check, the free capability probe, model discovery (`model/list`), account-change detection (`account/read` + 7D's keyed hash) and isolation from the user's `~/.codex`, the project's `AGENTS.md`/`.codex/` and every Codex feature Finisher did not enable work, tested against a `fake-codex` that speaks the same JSON-RPC and is checked against the pinned binary's generated schema.

## Global Constraints

**Code**
- MIT. No GPL/LGPL/AGPL/SSPL/EUPL dependency in shipped code (`pnpm gates`): **the platform package's `bwrap` is never copied, linked or shipped** (spec §17 excludes bubblewrap); a gate (Task 2) fails if any kept file is not on `pin.json`'s list. Codex is run unmodified, with documented flags and `-c` keys only; its login is the user's (spec §4.6, §8.6).
- **Finisher never opens, reads, copies or transmits anything under `<server-data>/providers/`** and never calls `account/login/*`, `account/logout`, `account/gatewayOAuth/*`, `account/bedrock/*`, `account/gcp/*`, `accountSession/*` or `feedback/upload` (Task 3's deny-list, Task 13's spy). Sign-in state is learned only from `account/read` and `account/updated`.
- **No cloud-only imports.** **Primitive ops live only in `fin-core`**: 7E adds none. **TypeScript model types are generated, never hand-written:** the protocol's Effect Schemas are generated from the committed schema (Task 3); no `fin-core` event kind is added (a new `AGENT_MODELS` row goes through the append-only snapshot).
- **File sizes:** non-test source ≤ 600 lines, tests ≤ 1,500; `generated/` is exempt (`scripts/check-file-size.mjs:13`); `runtime.ts`, `runtime-engine.ts`, `wiring.ts`, `rpc.ts` take call-site lines only.
- Errors are `{code, message, details, fix?}`; a new code goes into `crates/fin/src/output.rs`, `apps/finisherd/src/errors.ts` and `console/exit-codes.ts` (the parity test). 7E expects to need none beyond 7D's (`PROVIDER_VERSION`, `PROVIDER_AUTH`, `PROVIDER_ACCOUNT_CHANGED`, `ACCOUNT_CONFIRM_STALE`, `PROVIDER_PROTOCOL`, `PROVIDER_EXITED`, `PROVIDER_UNAVAILABLE`, `PRICING_UNKNOWN`, `MODEL_UNKNOWN`).

## Decisions taken here (the spec fixes the shape; these fix the details)

### The binary and the protocol

1. **The pin is 0.167.0** (spec §17's row; npm `latest`, ≥ 7 days old on 2026-11-13, `check:dep-age`'s rule). `vendor/codex/pin.json` = `{version, targets: {<npm suffix>: {integrity (sha512 from the registry), kept: ["bin/codex", "codex-path/rg"]}}}` for linux-x64, linux-arm64, darwin-x64, darwin-arm64, win32-x64 (`.exe`), win32-arm64. `scripts/codex-pin.mjs` (Task 2) downloads each tarball, checks its integrity, extracts **only** the kept files into `.cache/codex/<version>/<target>/` (git-ignored) and runs `generate-json-schema` and `features list` under a throwaway home to write `vendor/codex/<version>/{schema/, features.txt}`. `codex-code-mode-host` is not kept (`features.code_mode_host` off, Decision 6); Task 0 checks the app-server starts and runs a turn without it, `rg` and `bwrap`. **Where the server finds it:** `pin.ts` `codexBinary()` = `FIN_CODEX_BIN` (test-hooks builds only, so `fake-codex` or a fetched real binary can stand in) else `<resources>/codex/<target>/codex[.exe]` next to `finisherd` (sub-project 9 packages it), else the dev cache. There is no `agents.codex.path`: a user-selected `codex` is cut (§4.6).
2. **The protocol types are generated** (`scripts/gen-codex-protocol.mjs` → `agent/codex/generated/protocol.ts`): Effect Schemas for exactly the methods, notifications, server requests and their reachable definitions that `codex/` uses (a list in the script), from `vendor/codex/<version>/schema/` (stable plus the `--experimental` bundle for `dynamicTools` and `item/tool/call` only). Unknown object keys are ignored, unknown enum values and union members decode as `unknown` (drift is a notice), a missing required field the adapter reads is `PROVIDER_PROTOCOL`. **The drift gate** (`scripts/check-codex-protocol.mjs`, in `pnpm gates`): regenerating gives the committed file; every message `fake-codex` writes in its tests validates against the committed JSON schema (a small draft-07 validator in the test, no dependency); the method list in `rpc.ts` ⊆ the schema's. This is spec §4.6's "a test checks the vendored client's messages against it".
3. **The client** (`codex/rpc.ts`): T3's transport, vendored with its notice (`THIRD_PARTY.md` row): NDJSON framing (`\n` only, ≤ 16 MiB a line, 7D's `lineFramer` reused), numeric request ids, a pending map failed with `PROVIDER_EXITED` at EOF, server requests dispatched to one `RequestPort` (7D's shape), notifications to the mapper. **A method deny-list** in `rpc.ts` (`account/login/*`, `account/logout`, `account/gatewayOAuth/*`, `account/bedrock/*`, `account/gcp/*`, `accountSession/*`, `feedback/*`, `config/value/write`, `config/batchWrite`, `skills/config/write`, `plugin/install|uninstall`, `marketplace/*`, `externalAgentConfig/import*`, `thread/fork`, `fs/*`, `command/exec*`, `process/*`, `windowsSandbox/setupStart`) refuses at the call site; a test greps `codex/` for any of them.

### Launch and isolation

### The session

12. **One app-server per instance** (a ULID), events bound to it, a replaced instance's messages dropped; idle close after `agents.codex.idleCloseS` (default 300 s) and lazy `thread/resume` (`cli/instances.ts`, lifted from 7D Task 10); `provider.pid` recorded at spawn (`provider-pid.ts`). `providerRef = {kind: "codex", id: <threadId>}`, written to the session row **from the `thread/start` response before the first turn** (Codex picks the id); a crash between the two leaves an orphan thread in the session's own `provider/`, harmless.
13. **Turns:** `startTurn` sends `turn/start {threadId, input: [facts?, text]}` and emits `turnStarted`; the turn ends at `turn/completed` for that `turnId`. **Steer** sends `turn/steer {expectedTurnId: <active>}` (it joins the running turn, unlike Claude Code); a refusal (`activeTurnNotSteerable`, no active turn, an id race) holds the text and sends it as the next turn of the same run after `completed`, and an interrupted or failed turn hands held steers back as `notice {steerReturned}` (7D's owner decision of 2026-11-13, reused). `Capabilities.steer = true` (Owner question 4).
14. **Mapping** (`codex/map.ts`): `item/agentMessage/delta` → `messageDelta`; `item/reasoning/summaryTextDelta` → `reasoningDelta`; `item/completed` `agentMessage` → `message {assistant, blocks}`, `reasoning` → `reasoning {summary, text?}` (raw `content` only where emitted), `dynamicToolCall` (Finisher's shell) → nothing beyond the runtime's own call nodes, `fileChange` → `toolStarted {providerId: itemId, tool: "apply_patch", input: {changes}}` at `item/started` and `toolCompleted {ok: status == completed}` at `item/completed`, `webSearch` → a tool pair `WebSearch`, `plan` and `turn/plan/updated` → `plan`, `contextCompaction`/`thread/compacted` → `notice {compacted}`; `thread/tokenUsage/updated` → `usage` (Decision 15); `turn/completed` → `turnCompleted {stopReason}` or, `failed`, `turnFailed` from `codexErrorInfo` (`unauthorized` → `PROVIDER_AUTH {fix: "finisherd provider signin codex"}`, `usageLimitExceeded`/`rateLimitExceeded` → `PROVIDER_RATE_LIMITED`, `serverOverloaded` → `PROVIDER_OVERLOADED`, `modelNotFound` → `MODEL_UNKNOWN`, `contextWindowExceeded` → `PROVIDER_UNAVAILABLE {reason: contextWindow}`, `sessionBudgetExceeded` → `BUDGET_EXCEEDED`), `interrupted` while Finisher interrupts → `turnCompleted {stopReason: interrupted}` (an interrupt Finisher did not ask for is `turnFailed`, 7D part B S1); `error {willRetry: true}` → `notice {retry}`; `warning`, `configWarning`, `deprecationNotice`, `model/rerouted` → notices; `collabAgentToolCall`, `subAgentActivity`, `mcpToolCall` (no server is configured), `imageGeneration`, `hookPrompt`, `enteredReviewMode` → `notice {unexpected: <kind>}` **and the instance is killed** (isolation broke); `commandExecution` with `source: agent` likewise (the shell tool is off); any other method → `unknown` once per name.
15. **Usage:** `usage.ts` charges each `thread/tokenUsage/updated` as the delta of `total` over the instance's last seen `total` (cached input weighted as 7A does, `reasoningOutputTokens` as `reasoning`), so a token budget stops a turn mid-way through the runtime's own budget stop; the turn's `turn/completed` settles the gate's per-turn reservation (`gate.beforeCall` once per turn, 7D Task 9's `TURN_ESTIMATE_TOKENS`). **On a resumed instance** the first `total` is charged in full unless `provider.pid`'s baseline (a clean end) pins it (7D's fail-closed `restoredOffset`, `provider-pid.ts` `CliBaseline`); an `updated` arriving after the run closed is the session's last run's (`#lateUsage`). Money per Decision 11, at the turn's model price.
16. **Interrupt:** `turn/interrupt {threadId, turnId}`; wait for `turn/completed {interrupted}` ≤ 5 s; then close stdin, then the sandbox's group kill. A Finisher `shell` call in flight is killed through its own process group (it is `finisherd`'s child) and gets the runtime's synthetic `SESSION_INTERRUPTED` result; its `item/tool/call` is answered `success: false` before the interrupt if still open.
17. **Crash and resume:** an exit with a turn open fails it `PROVIDER_EXITED {code, signal}`; `recoverAfterCrash`'s orphan sweep (already there) kills a recorded app-server still alive with its start time. Resume = a new instance, `thread/resume {threadId, <same overrides>}`; the synthetic results of the last process's open calls go in the next turn's first input item (`cli/resume.ts`); a dynamic `shell` call for a `callId` an earlier process announced is answered `success: false` with "not run again after a restart" (no re-run, Review Focus 5). `thread/resume` of a thread the `provider/` dir lacks → `PROVIDER_EXITED {reason: transcriptLost}` with 7D's fix text. Whether `thread/inject_items` can carry the synthetic results as real function outputs is [Task 0]; until then, text.
18. **Rollback is a capability** (spec §4.2 "where offered", §5.3; TASKS.md line 1487): the session records each run's Codex `turnId`s (a `turnIds` field on the run's `turnStarted` node payload, no migration); `ProviderSession.rollback(toTurn)` (7B's `agent.session.rollback` after it undid the transactions) sends `thread/revert {threadId, beforeTurnId: <first turn of run toTurn+1>}`; Codex "doesn't change local files", and Finisher's transactions were already undone, so the two agree. A `threadRollbackFailed` error leaves 7B's `conversation: kept` answer. `Capabilities.rollback = true` (Owner question 6).
19. **Permission requests** (`codex/permissions.ts`): `item/fileChange/requestApproval` → `request {kind: approval, tool: "apply_patch", input: {path: <each change's path>, changes}}` (one request per item; every path must pass `permissions.ts`'s write check, Q3a's `realTarget` included, else deny); `item/tool/call` → Decision 9; `item/commandExecution/requestApproval` (cannot arise: no Codex shell) → `decline` and a notice; `item/permissions/requestApproval` → an empty grant (`{permissions: {}}`) and a notice; `item/tool/requestUserInput` and `mcpServer/elicitation/request` → declined (no `userInput` path in v1 for CLIs); `account/chatgptAuthTokens/refresh` and `attestation/generate` → JSON-RPC error `-32601` (Finisher holds no tokens). **Answers are only `accept` or `decline`**: never `acceptForSession`, `cancel`, `acceptWithExecpolicyAmendment` or `applyNetworkPolicyAmendment` (a remembered allow is a Finisher rule, 7B Decision 12; Finisher never rewrites inputs, §12.3). `serverRequest/resolved` for a request Finisher has not answered → `requestCancelled {id}` → `ProviderRequests.withdraw`. Q3a (`unconfined`) applies unchanged: while the profile is not enforced, `shell` asks and patches outside `workspace/<session>/` are denied in every mode.
20. **Account change** (spec §8.6): each instance's `account/read` (never `refreshToken`) gives `{type, email, planType}`; the label is `email`; a `chatgpt` account without one is `PROVIDER_ACCOUNT_CHANGED {reason: noAccountLabel}` (7D Task 11 review: fail closed); an `apiKey` account names no account at all (as built, 7D's `accountIdentified`, `claude/account.ts:128`, refuses such a sign-in), which Owner question 7 settles; hashed with `cli/account.ts`'s HMAC into `agents/codex-account.json`; a change stops new Codex sessions `PROVIDER_ACCOUNT_CHANGED` until `finisherd provider account confirm codex` (the 7D flow, harness-parameterised). `account/updated` mid-instance re-reads the account and, on a change, refuses the next new session (running ones continue, 7D). *Residual, as 7D:* the hash is of what the CLI reports; a session that swaps `auth.json` for another account's is seen at the next instance's `account/read`, which is the point of reading it per instance.
21. **Sign-in:** `finisherd provider signin codex` prints, and runs nothing: `CODEX_HOME=<server-data>/providers/codex/home <bundled codex> -c cli_auth_credentials_store="file" login` and the `--device-auth` variant for a headless server (PowerShell quoting on Windows, 7D Task 3); `signout` prints `logout` the same way; `--confirm` marks the next account change expected (7D). **The refresh path** (TASKS.md line 1544): Task 0 traces whether a token refresh rewrites `auth.json` in place or by rename; by rename, the per-session link would be replaced by a private copy, so the store becomes Claude Code's form (a store-only directory) if Codex offers a variable for it, else spec §8.6's fallback (the sign-in home as `CODEX_HOME`, settings via `-c` only, the home's other files in `protect`), recorded in `agent.providers`.

   - **(a, recommended)** Finisher: Codex's shell tools off, one `shell` dynamic tool (an `experimentalApi` field of the pinned schema) that `finisherd` decides and runs through the session sandbox.
